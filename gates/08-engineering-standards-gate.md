# 日常工程规范门禁

## 检查对象

适用于任何新增或修改的代码、配置、API、UI、脚本、测试和文档。

## 必须检查

- 目录和文件是否归属正确模块？
- 是否存在当前树、目标树和文件归属清单？
- 新增、移动、删除文件是否同步更新了文件树？
- 新增源文件是否进入构建、测试、资源或发布注册？
- 生成文件是否能追溯到生成器和源输入，秘密和本地状态是否被排除？
- 命名是否使用项目统一词汇？
- 是否存在重复真源、魔法值或隐藏全局状态？
- 函数是否混合多个责任和副作用？
- 输入、错误、取消、重试和资源释放是否明确？
- 日志是否结构化且脱敏？
- 配置是否有默认值、范围、版本和迁移？
- 时间、金额、编码、ID 和路径是否有明确类型/语义？
- 异步回调是否有生命周期和版本保护？
- 公共 API 是否有错误码、权限和兼容策略？
- 测试是否验证行为和失败路径？
- 注释是否解释原因而不是重复代码？
- 是否记录了变更范围、非目标和影响面？
- 是否检查旧客户端、旧配置、旧数据和降级组合？
- 新依赖是否完成版本、来源、许可证、漏洞和回滚检查？
- 配置来源优先级、敏感级别和失败行为是否明确？
- 迁移是否有预检查、备份、幂等性、校验和恢复方案？
- 重要操作是否有足够的日志、指标、追踪或诊断证据？
- UI、API、CLI 是否覆盖加载、空、禁用、失败、取消和重试状态？
- AI 生成或自动修改的内容是否经过源码、构建、测试和安全核验？
- diff 是否没有无关格式化、秘密和临时文件？

## 建议检查命令

按项目实际工具执行：

```text
格式化检查
编译/类型检查
静态分析
依赖和许可证扫描
敏感信息扫描
受影响测试
构建目标
git diff --check
```

## 阻塞条件

- 新代码违反项目已有规则
- 业务规则复制到多个真源
- 错误被吞掉或失败后继续破坏数据
- 有未受控的资源、线程、任务或连接泄漏
- 用户可见文本绕过项目 i18n
- 真实功能被占位按钮或静态数据伪装
- 测试没有运行真实当前构建
- diff 含凭据、个人路径或生成物
- 变更没有明确范围，或无关 diff 已超过可解释范围
- 实际文件树包含清单没有解释的本次新增文件
- 文件已创建但没有构建、测试、资源、迁移、插件或发布注册
- 公共 API、配置、协议或文件格式变更没有兼容策略
- 迁移会覆盖唯一数据且没有可验证备份
- 依赖来源、许可证或安全风险无法说明
- 取消后仍继续执行副作用，或失败后状态不一致
- 交付报告把未执行命令、旧日志或推测写成通过

## 通过证据

交付记录至少包含：

```text
规范检查：
执行命令：
结果：
未通过项：
豁免原因：
后续期限：
变更范围：
兼容性矩阵：
依赖/许可证证据：
迁移/回滚证据：
可观测性证据：
AI 生成内容核验：
```
